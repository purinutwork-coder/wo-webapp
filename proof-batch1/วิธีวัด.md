# วิธีวัดกองที่ 1 ข้อ 2 — ทำด้วยมือบนเครื่องตัวเอง

คู่มือนี้มีไว้ให้คนรันเอง ไม่ต้องใช้ผู้ช่วยตัวไหน · ใช้แค่ `wrangler` กับ `curl`

> **ทำไมต้องรันบนเครื่องตัวเอง** — คอนเทนเนอร์บนคลาวด์ถูกนโยบายเครือข่ายปิดกั้น
> `api.cloudflare.com` และ `wrangler login` ต้องเปิดเบราว์เซอร์ให้คนกด Allow
> ซึ่งทำได้เฉพาะบนเครื่องที่มีหน้าจอจริง

## ของที่ต้องมี

- Node.js กับ npm
- บัญชี Cloudflare ที่ deploy Worker ได้
- anon key ของ Supabase — เอาจาก Supabase Dashboard → Project Settings → API
  → ช่อง `anon` `public` · **ห้ามใช้ `service_role` เด็ดขาด** (CLAUDE.md ข้อ 22)

## ขั้นที่ 2 — deploy แล้วตั้งความลับ

```bash
npx wrangler deploy
```

ครั้งแรกมันจะเปิดเบราว์เซอร์ให้กด **Allow** และอาจให้ตั้งชื่อ workers.dev subdomain ·
**จดที่อยู่ที่มันพิมพ์ออกมาตอนจบ** หน้าตาประมาณ
`https://wo-probe-fetch.<ชื่อคุณ>.workers.dev`

```bash
npx wrangler secret put PROOF_TOKEN        # สุ่มยาว ๆ จำไว้ ต้องใช้ตอนยิง
npx wrangler secret put SUPABASE_ANON_KEY  # anon เท่านั้น
```

ไม่ตั้ง `PROOF_TOKEN` = Worker ปิดตายตอบ 503 ทุกทาง · ไม่ตั้ง `SUPABASE_ANON_KEY` =
ข้อ 1 ตอบเคสที่สำคัญที่สุดไม่ได้

ตรวจว่าตั้งครบแล้ว — เปิดที่อยู่ของ Worker ในเบราว์เซอร์ หน้าแรกจะบอกเองว่า
`ความลับที่ตั้งแล้ว` มีอะไรเป็น `true` บ้าง

## ขั้นที่ 3 — ยิงให้ครบหกทาง

**macOS · Linux · Git Bash บน Windows**

```bash
T='<รหัสที่ตั้งไว้>'
B='https://wo-probe-fetch.<ชื่อคุณ>.workers.dev'

for p in body4xx netfail retry unread; do
  curl -sS --max-time 120 -H "x-proof-token: $T" "$B/$p" > "ผล-$p.json"
  echo "เสร็จ $p"
done

curl -sS --max-time 180 -H "x-proof-token: $T" "$B/timeout"     > ผล-timeout.json
curl -sS --max-time 600 -H "x-proof-token: $T" "$B/subrequests" > ผล-subrequests.json
```

**PowerShell บน Windows**

```powershell
$T = '<รหัสที่ตั้งไว้>'
$B = 'https://wo-probe-fetch.<ชื่อคุณ>.workers.dev'
$H = @{ 'x-proof-token' = $T }

foreach ($p in 'body4xx','netfail','retry','unread') {
  Invoke-WebRequest -Uri "$B/$p" -Headers $H -TimeoutSec 120 |
    Select-Object -ExpandProperty Content | Out-File -Encoding utf8 "ผล-$p.json"
  Write-Host "เสร็จ $p"
}

Invoke-WebRequest -Uri "$B/timeout" -Headers $H -TimeoutSec 180 |
  Select-Object -ExpandProperty Content | Out-File -Encoding utf8 'ผล-timeout.json'
Invoke-WebRequest -Uri "$B/subrequests" -Headers $H -TimeoutSec 600 |
  Select-Object -ExpandProperty Content | Out-File -Encoding utf8 'ผล-subrequests.json'
```

สองทางหลังแยกออกมาเพราะช้า — `/timeout` ตั้งใจค้าง 35 วินาที ส่วน `/subrequests`
ไต่ถึง 1,200 คำขอ

## ขั้นที่ 4 — ตรวจผลก่อนเชื่อ

| ไฟล์ | ต้องดูอะไร |
| --- | --- |
| `ผล-body4xx.json` | เคสแรกต้อง**ไม่ใช่** `"ผล": "ไม่ได้วัด"` · ถ้าใช่ แปลว่ายังไม่ได้ตั้ง `SUPABASE_ANON_KEY` และเคสสำคัญที่สุดของข้อ 1 ยังไม่มีคำตอบ · ดูช่อง `แกะcodeได้` กับ `postgrest.code` |
| `ผล-retry.json` | ต้องได้ `"ผล": "วัดได้"` · ถ้าได้ `"วัดไม่ได้ในรอบนี้"` แปลว่าสามคำขอตกคนละ isolate **ให้ยิงซ้ำ** อย่าเอารอบนั้นมาใช้ |
| `ผล-timeout.json` | ดูช่อง `ใครจบรอบนี้` — "ฝั่งที่ค้างตอบเอง" กับ "มีใครฆ่ากลางทาง" ให้คำตอบตรงข้ามกันเรื่องต้องใส่เพดานเวลาใน `httpSend_` ไหม |
| `ผล-subrequests.json` | ดูช่อง `สำเร็จ` กับ `เทียบกับของจริง` ว่าเกิน 62 คำขอไหม |
| `ผล-netfail.json` | ดูว่าแต่ละเคส `คืน Response` หรือ `โยนออกมา` — กฎข้อ 24 ลองใหม่ได้เฉพาะ 5xx กับ timeout |
| `ผล-unread.json` | ดูว่า `พังตอนรอบไหน` เป็น `null` หรือมีเลข |
